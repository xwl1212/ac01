# Week 2 · PWM 呼吸灯 + 串口命令调光

基于 STM32F103C8T6 的可交互调光节点：TIM2 通道 2 输出 1kHz PWM 驱动共阳极 LED，USART1 接收命令实时切换亮度模式，环形缓冲 + 行解析保证连续输入不丢字节。

## 硬件

| 用途 | 引脚 | 说明 |
|---|---|---|
| PWM 输出 | PA1 / TIM2_CH2 | 复用推挽，驱动共阳极 LED |
| 按键指示 | PA3 | GPIO 输出，按键反馈亮 1 秒 |
| 串口指示 | PA2 | GPIO 输出，串口收到字节点亮 1 秒 |
| 按键输入 | PA0 / EXTI0 | 上升沿触发 |
| 串口 | USART1 | 115200 / 8N1，CMSIS-DAP 虚拟串口 |
| 心跳定时 | TIM3 | 500ms 中断，计数值打印 |

## 命令集

| 命令 | 作用 | 回显 |
|---|---|---|
| `SET n`（n = 0~100） | 固定亮度，n 为亮度百分比 | `OK SET n` |
| `BREATH` | 呼吸模式（默认模式） | `OK BREATH` |
| `STOP` | 全灭 | `OK STOP` |
| 其他 | 不动作 | `ERR unknown` |

另外每秒打印一次 `tick=<n>`，用于确认 TIM3 中断与主循环均在运行。

## 实现要点

**1. PWM 由硬件生成，CPU 只负责改数字**

TIM2 配置 PSC = 71、ARR = 999：72MHz / 72 = 1MHz 计数频率，1MHz / 1000 = 1kHz PWM，周期 1ms，共 1000 级亮度。波形由定时器硬件持续输出，CPU 阻塞在延时里也不影响波形。

**2. CCR 与亮度是反相关系**

PWM mode 1 + 极性 High：`CNT < CCR` 输出高电平，`CNT >= CCR` 输出低电平。共阳极 LED 低电平点亮，因此 CCR 越小，低电平占比越大，视觉越亮。`SET n` 归一化时用 `(100 - n) * 10` 把亮度百分比映射到 CCR。

**3. 全灭写 CCR = ARR + 1**

`CCR = 999` 仍会在 `CNT = 999` 时产生 1µs 低电平（占空比 0.1%，暗环境下可见微亮）。全灭必须写 `1000`：`CNT` 最大只到 999，永远不满足比较条件，输出恒高电平。

**4. 环形缓冲解耦中断与主循环**

串口中断每次只接收 1 字节，写入 `rx_buf` 后推进写指针 `rx_head`；主循环用读指针 `rx_tail` 逐个消费。指针推进统一用 `% RX_SIZE` 回绕，缓冲区满时丢弃新字节并累加 `rx_drop`。这样突发数据不会因主循环处理慢而丢失，读指针在消费后必须推进，否则会重复读取同一字节导致死循环。

**5. 行解析按字节累积**

主循环把字节追加到 `cmd_buf`，遇到 `\r` / `\n` 认为一条命令结束，补 `\0` 后交给解析器；长度限制为 `CMD_MAX - 1`，留一格给结束符防止越界。解析用 `strncmp` 比较前缀（`SET ` 带空格，避免把 `SETTING` 误判），数值用 `atoi` 转换后夹到 0~100。

**6. 非阻塞软件定时**

按键与串口指示灯的 1 秒延时不用 `HAL_Delay`，而是记录 `HAL_GetTick() + ms` 作为到期时间戳，主循环轮询比较，到点清零标志。到期时间置 0 表示未激活，避免重复触发。

**7. 中断与主循环的分工**

中断回调只做最小动作：串口回调写入缓冲区并重挂接收，按键回调置标志，定时器回调累加计数。所有命令解析、状态切换、寄存器写入都在主循环完成，避免在中断上下文中执行耗时或不可重入的逻辑。

## 构建

- STM32CubeMX 6.14.1（F1 固件包 V1.8.6）重新生成工程
- Keil MDK 5.36（ARMCC V5.06 update 7）编译下载
- 串口助手 115200 / 8N1，发送命令需带换行

## 已知限制

- 呼吸步进固定为 5 档 / 每轮，速度调整需同步改步长或循环延时
- 主循环使用 `HAL_Delay(10)` 阻塞延时，接入更多外设后需改为时间片调度
- 命令仅支持三条，无参数回读与错误码细分
